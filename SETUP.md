# Setting up "Add a recipe"

The site itself stays on GitHub Pages. Adding a recipe goes through a small helper running on Cloudflare (free). The helper:

1. Checks the passcode.
2. Sends the pasted text or screenshots to Claude, which writes the recipe in the house format.
3. Saves the recipe into this repo.

GitHub then rebuilds the site, which takes about 2 minutes.

```
phone/browser ──> Cloudflare helper ──> Claude API   (reads and formats the recipe)
                         └────────────> GitHub repo  (saves library/recipes/<id>.json)
GitHub Actions ──> builds library/recipes.json ──> GitHub Pages
```

Your keys live only in Cloudflare's secret settings. They are never in the website or the repo.

## 1. Let GitHub Actions publish the site (1 min)

1. Open the repo on GitHub: **Settings → Pages**.
2. Under **Build and deployment → Source**, choose **GitHub Actions**.

From then on, every change, including recipes saved from the website, runs the "Build and publish site" workflow. It checks every recipe file and fails safely if one is broken, so the live site keeps the last good version.

## 2. Get a Claude API key (5 min)

1. Go to <https://console.anthropic.com> and sign in or create an account.
2. Under **Billing**, add a small amount of credit. $5 lasts a long time at family volume.
3. Optional: under **Limits**, set a monthly spend limit.
4. Under **API keys**, create a key named `kitchen-helper` and copy it. It starts with `sk-ant-`.

**Cost:** the default model, `claude-opus-5-5`, costs roughly 5–15¢ per recipe. To spend less, change `MODEL` in `worker/wrangler.toml` to `claude-haiku-5-5`, which costs well under 1¢ but is less careful with messy screenshots.

## 3. Make a GitHub token for the helper (3 min)

1. Go to GitHub: **your picture → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Fill in:
   - **Name:** `kitchen-helper`
   - **Expiration:** 1 year (set a reminder to renew it)
   - **Repository access:** *Only select repositories* → `AirPengwn/erinskitchen`
   - **Permissions → Repository permissions → Contents:** *Read and write*
3. Generate it and copy it. It starts with `github_pat_`.

This token can only change files in this one repo.

## 4. Pick a passcode

Anyone who has the passcode can add recipes. Use a short phrase of 4 or more random words, like `maple tractor seven lantern`, and share it with whoever should be able to add recipes. Each device remembers it after the first use.

## 5. Put the helper on Cloudflare (5 min)

1. Create a free account at <https://dash.cloudflare.com/sign-up>.
2. In a terminal, from this repo's `worker` folder:

   ```bash
   npm install
   npx wrangler@4 login
   npx wrangler@4 deploy
   ```

   - `login` opens a browser window. Approve it there.
   - The first `deploy` asks you to pick a `workers.dev` subdomain.
   - When `deploy` finishes, it prints the helper's address, like `https://kitchen-helper.<you>.workers.dev`.
3. Add the three secrets. Either use the Cloudflare dashboard: **Workers & Pages → kitchen-helper → Settings → Variables and Secrets → Add**, type **Secret**, one for each:

   | Name | Value |
   |---|---|
   | `ANTHROPIC_API_KEY` | the `sk-ant-…` key from step 2 |
   | `GITHUB_TOKEN` | the `github_pat_…` token from step 3 |
   | `PASSCODE` | your passcode from step 4 |

   Or run `npx wrangler@4 secret put ANTHROPIC_API_KEY` (and the same for the other two) and paste each value when asked.

## 6. Point the website at the helper

Put the helper's address in `site.json` at the top of the repo and commit:

```json
{
 "worker": "https://kitchen-helper.<you>.workers.dev"
}
```

## 7. Try it

1. Open the site and tap **+ Add a recipe**.
2. Paste a recipe or add a screenshot, enter the passcode and tap **Read recipe**.
3. Check the preview. If something's wrong, describe it under **Something off?**, choose where the recipe goes, and tap **Save recipe**.

## How the data is laid out

| Path | What it is |
|---|---|
| `library/recipes/<id>.json` | One file per recipe, shared by everyone. Edit these on GitHub to fix a recipe. |
| `library/recipes.json` | All recipes combined. Generated by `scripts/build-library.mjs`; don't edit by hand. |
| `people/<name>.json` | One person's page: name, photo, sections, and their **box**, meaning which recipes they've made or might like, plus their notes. |
| `people/<name>.jpg` | Their header photo. |
| `index.html` | Erin's page. Another person's page is a copy in its own folder, with `person` and `root` changed. |
| `app/app.js`, `app/app.css` | The shared site code. |
| `site.json` | The helper's address. |
| `worker/` | The Cloudflare helper. `npm test` runs its offline tests. |

## Adding a second person

1. Create `people/<name>.json` (copy Erin's file and empty the `box`) and `people/<name>.jpg`.
2. Copy `index.html` to `<name>/index.html`. In the copy:
   - Set `window.KITCHEN = { person: "<name>", root: "../" }`.
   - Point the `app/` and `people/` links at `../`.
   - Replace the "About her cooking" part.

Both pages read the same `library/`. A recipe added from either page lands in the shared library. It only appears in a person's box if the person adding it chose that.
